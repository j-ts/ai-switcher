# Research track: os-credstores

_Research date: 2026-10-07. Claims are marked VERIFIED (evidence gathered during the research) or INFERRED._

## Summary

I pulled the real credential-storage code paths out of the shipped binaries and sources and ran live tests on Ubuntu 24.04 (dbus 1.14.10, gnome-keyring 46.1, libsecret 0.21.4). Antigravity CLI 1.3.1 (agy) embeds Google's vendored copy of zalando/go-keyring (MIT); its single login slot is service="gemini", account="antigravity", stored in the macOS login keychain via /usr/bin/security, in Secret Service on Linux, and in Windows Credential Manager as TargetName "gemini:antigravity". agy also keeps a plaintext JSON file fallback (~/.gemini/antigravity-oauth-token, mode 0600) and switches to it whenever it detects SSH, WSL, a container, no D-Bus session, or a recent keyring timeout, so a swap sometimes means swapping a file, not a keychain entry. On macOS the only way to avoid "allow access" prompts on a foreign item is to go through /usr/bin/security as agy and Claude Code do; macOS 26.x has already caused partition-list lockouts in Claude Code. On Linux and Windows there is no per-application access control, so any process of the same user can read and write the slot; what fails there is availability (headless gnome-keyring has no login collection, a locked collection cannot prompt and fails in ~18 ms, godbus tries to autolaunch dbus-launch, and Windows Credential Manager does not work over network/SSH logons and caps a credential at 2560 bytes). Every surveyed CLI (Claude Code, Codex, gh, agy, docker, GCM) falls back to a 0600 plaintext file or an explicit opt-in store when no keyring is present. Recommended design: an envelope vault where the OS store holds only one 32-byte key and all per-account secrets live in one XChaCha20-Poly1305 file (0600, atomic rename, file lock), with DPAPI, an Argon2id passphrase (optionally cached in the Linux kernel keyring), or an explicit key file as fallbacks, and a non-interactive mode that never prompts. Go (zalando/go-keyring, godbus, danieljoos/wincred, x/sys) cross-compiles with CGO_ENABLED=0 to all six targets at ~3 MB and reproduces agy's slot encoding byte-for-byte because agy uses the same library; the Rust stack works on Linux but needs extra linkers/SDKs to cross-compile and pulls in ~126 crates, so for the credential-store layer Go is the lower-risk choice.

## Full report

All claims labelled VERIFIED (evidence gathered now, cited) or INFERRED (memory/reasoning). Env: Ubuntu 24.04.5 x86_64; Go 1.24.7; rustc 1.97.0; dbus 1.14.10; gnome-keyring 46.1; libsecret-tools 0.21.4; gcr-prompter present, no X display.

## 0. TL;DR decision
- **Own secrets → envelope vault.** One encrypted file `vault.v1.bin` (XChaCha20-Poly1305, 0600, atomic rename, flock). Its 32-byte data key lives in the OS store, else a fallback.
- **macOS key store:** `/usr/bin/security` (absolute path), write via `security -i` on stdin, read via `find-generic-password -w`. Never `-A`, never `-T ""`, never edit partition lists.
- **Linux key store:** Secret Service over godbus with an explicit bus address (no autolaunch); check `Locked` before `Unlock`; in unattended mode never `Unlock`.
- **Windows key store:** `CRED_TYPE_GENERIC`, `CRED_PERSIST_LOCAL_MACHINE`, TargetName `accshift:vault-key-v1`; on `ERROR_NO_SUCH_LOGON_SESSION` (1312) fall back to a DPAPI-wrapped key file.
- **No keyring (headless/WSL/container/SSH):** Argon2id passphrase key (optionally cached in the kernel `@u` keyring) or an explicit opt-in 0600 key file.
- **agy:** swap under a lock, only while agy is not running; snapshot the outgoing account first; write the incoming blob in agy's exact native encoding into whichever slot agy will use (keyring item OR agy's own token file); read back to verify; journal for crash recovery.
- **Claude:** no swap, inject `CLAUDE_CODE_OAUTH_TOKEN`; backup plan per-account `CLAUDE_SECURESTORAGE_CONFIG_DIR` confirmed in code.
- **Codex:** per-account `CODEX_HOME` isolates its keyring key automatically (`cli|sha256(canonical CODEX_HOME)[:16]`); do not keep stale token copies (rotating refresh tokens — INFERRED).

## 1. agy slot (VERIFIED, static analysis; binaries not executed)
Manifests at `antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/*.json` → v1.3.1; downloaded, sha512 matched (linux `3b8349d7…1f68`). Inspected with `strings`, a custom pclntab parser (agy's function table in `.lrodata`, 155,630 funcs), and `objdump -d`.

Libraries (symbol strings): Linux `zalando/go_keyring/.../keyring.secretServiceProvider.{Get,Set,Delete}`, `secret_service/ss.(*SecretService).Unlock`, label `Password for '%s' on '%s'`; macOS `keyring.(*macOSXKeychain).Set`, `/usr/bin/security`, `add-generic-password -U -s %s -a %s -w %s`, `go-keyring-base64:`; Windows `danieljoos/wincred/.../wincred.sysCredWrite/sysCredRead`.

It derives file fallback `join(dir, prefix+"-oauth-token")` and timeout marker `join(dir,"cache",prefix+"-keyring-unavailable")`.

Native encoding (from go-keyring v0.2.8 source):
- Linux: Secret Service item in collection `login` (else alias `default`), attrs `{service:gemini, username:antigravity}`, label `Password for 'antigravity' on 'gemini'`, session `plain`, `CreateItem(replace=true)`.
- macOS: login-keychain generic password `-s gemini -a antigravity`, written via `security -i` stdin `add-generic-password -U -s gemini -a antigravity -w go-keyring-base64:<b64>`; refused if that line >4096 bytes. Read via `find-generic-password -s gemini -wa antigravity`, strip `go-keyring-base64:` / hex `go-keyring-encoded:`.
- Windows: `CredWriteW`, `CRED_TYPE_GENERIC`, TargetName `gemini:antigravity`, UserName `antigravity`, blob = raw UTF-8 bytes, `Persist=LOCAL_MACHINE`; refused >2560 bytes.
- File: `<appDataDir>/antigravity-oauth-token`, plaintext JSON, `MkdirAll 0755` + `WriteFile 0600` (imms 0x1ed, 0x180). appDataDir INFERRED `~/.gemini` (`newServerBackendConfig` joins `.gemini`; `DefaultKeyringMarkerPath` uses `$HOME/.gemini/cache/...`).

Keyring-bypass (VERIFIED strings in `codeassistclient`): functions `shouldBypassKeyring`, `containerDetector`(`/.dockerenv`, `/proc/1/cgroup` docker/containerd/kubepods), `dbusDetector`(`no D-Bus session bus`/`DBUS_SESSION_BUS_ADDRESS`), `sshDetector`(`SSH_TTY`/`SSH_CLIENT`/`SSH_CONNECTION`), `wslDetector`(`WSL_DISTRO_NAME`/`WSL_INTEROP`/`/proc/sys/kernel/osrelease`), `androidDetector`. Log: `Using file-based token storage because %s detected` / `… keyring timeout … within the last %v` / `… the caller requested it`; `keyringAuth: timed out after %v, skipping keyring auth`. Same detector strings appear in the macOS and Windows builds (whether they fire there is open).

Implications: swap the slot agy will actually use in the queue's environment; never swap while agy/daemon runs (it has `remotecontrol.(*Daemon).SeedToken`, `failed to write daemon token file`); Go reproduces the encoding exactly.

## 3. macOS Keychain
TN3137 (current, mentions macOS 26.4): file-based vs data-protection keychains; "Programs that read existing items in a file-based keychain must target the file-based keychain"; data-protection keychain needs entitlements "authorized by a provisioning profile" (not standard for CLIs); "The keychain support in the security command-line tool is primarily focused on the file-based keychain"; since macOS 26.4 keychain files may depend on protected entropy in `/var/db/SystemKeys`. agy/Claude items are file-based login-keychain items.

security(1) man source (apple-oss-distributions/Security, security.1): `add-generic-password [-a][-s][-w][-U][-X hex][-l][-A|-T appPath]`; `-A`="Allow any application to access this item without warning (insecure, not recommended!)"; `-T ""` removes default creator access; `-w` last prompts; `find-generic-password` `-g`/`-w`; `set-generic-password-partition-list -S <list> -k <pw>` "You must present the keychain's password"; `unlock-keychain [-u][-p pw]`; `-i` interactive reads commands from stdin (how go-keyring/Claude keep secrets out of argv).

Prompt causes (INFERRED unless noted): caller not in ACL (framework API vs `security`-created item); code signature not in partition list (VERIFIED via #62361/#81707, incl. macOS 26.5 shrinking to `apple-tool:`); locked keychain (GUI dialog, else `errSecInteractionNotAllowed`); partition-list change needs the keychain password.
Recommendation: read/write both foreign and own items through `/usr/bin/security` → ACL keeps trusting `security`, partition stays `apple-tool:`, no prompts; a direct-framework design ties the ACL to accshift's (ad-hoc, changing) code identity and would prompt after each release.
Exit codes = low byte of OSStatus (computed, matches Claude Code): errSecItemNotFound -25300→44; errSecInteractionNotAllowed -25308→36; errSecNoDefaultKeychain -25307→37; errSecNoSuchKeychain -25294→50; errSecAuthFailed -25293→51; errSecDuplicateItem -25299→45.
SSH + locked login keychain (web, INFERRED for current macOS): GUI login unlocks it, SSH does not; `security find-generic-password` → "User interaction is not allowed"; fix `security unlock-keychain ~/Library/Keychains/login.keychain-db`. accshift must detect exit 36 and print that hint, and never store the login password.
Size: no small item limit documented; practical limit is the `security -i` line (go-keyring 4096, Claude 4032). accshift's own item is a 44-char base64 key, so irrelevant.

## 4. Linux Secret Service + alternatives
Providers: gnome-keyring (tested); KWallet since KDE Frameworks 5.97 via `ksecretd` exposing `org.freedesktop.secrets`; KeePassXC since 2.5.0 (exposes a chosen DB/group; collection naming may differ); oo7-daemon planned default for Fedora 45, migrates gnome-keyring/KWallet, mentions "scoped authorization … for applications" (impact on cross-app reads = open).

Live experiments (VERIFIED, fake data, isolated HOME + `dbus-run-session`):
1. No session bus: go-keyring → `exec: "dbus-launch": executable file not found` (godbus autolaunches dbus-launch); secret-tool → `Cannot autolaunch D-Bus without X11 $DISPLAY`.

3. `printf pw | gnome-keyring-daemon --unlock --components=secrets --daemonize` first: `login` collection created, unlocked, default; go-keyring and secret-tool interoperate on the agy-format item (`attribute.service=gemini`, `attribute.username=antigravity`, `schema=org.freedesktop.Secret.Generic`).
4. Sizes 2560 B / 4 KiB / 64 KiB / 1 MiB / 8 MiB all round-trip; 8 MiB set 838 ms.
5. Locked collection, no display: go-keyring & secret-tool fail fast (~18 ms); a second `gnome-keyring-daemon --unlock` (±`--replace`) did NOT re-unlock (exit 0, still Locked).
6. agy-slot swap alice→bob with flock: 11 ms, read-back equal, exactly 1 item before/after (replace=true), second flock EWOULDBLOCK.
7. Envelope vault: 32-byte key in Secret Service, XChaCha20-Poly1305 file 634 B mode 0600, no plaintext, round trip 8 ms.
8. Argon2id t=3 m=64MiB p=4: 229 ms.
9. Kernel keyring (add_key/keyctl @u/@s/persistent) works here; `persistent_keyring_expiry`=259200 s; Docker default seccomp blocks add_key/keyctl/request_key ("not namespaced").
10. Rust keyring-core 1.0.0 + zbus-secret-service-keyring-store 1.0.1 (crypto-rust) read the go-keyring item OK (11 ms); on a locked collection it calls Unlock → `prompt dismissed`. Binary 2.17 MB, build 28 s, 126 crates.

Code hazard (VERIFIED go-keyring v0.2.8): `handlePrompt` blocks on `<-promptSignal` with no timeout → a locked desktop collection can hang an unattended run; gh mitigates with 60 s timeouts. accshift: `Connect(addr)` (no autolaunch), read `Locked`, never `Unlock` in non-interactive mode, context timeouts (probe 3 s / op 10 s).
secret-tool packaging (diagnostics only; accshift speaks D-Bus natively): Debian/Ubuntu `libsecret-tools`; Arch `libsecret`; Alpine edge `libsecret`; Fedora `libsecret`.
WSL/containers/headless: usually no bus/Secret Service (INFERRED); agy itself uses file storage there (VERIFIED) → accshift uses file/passphrase key source too.

## 5. Windows
CREDENTIALW / CredWriteW (Microsoft Learn): `CRED_TYPE_GENERIC`; TargetName ≤32767 (`CRED_MAX_GENERIC_TARGET_NAME_LENGTH`), case-insensitive, suggest company/service prefix; `CredentialBlobSize` ≤ `CRED_MAX_CREDENTIAL_BLOB_SIZE` (5*512=2560); generic blob "defined by the application"; UserName ≤513; Comment/TargetAlias ≤256; ≤64 attrs; Persist SESSION/LOCAL_MACHINE/ENTERPRISE(roams); `CredWrite` returns `ERROR_NO_SUCH_LOGON_SESSION` ("Network logon sessions do not have an associated credential set"). No per-app access control (INFERRED) so swapping agy's `gemini:antigravity` is prompt-free. Do not use `cmdkey` for agy's slot (cannot read; writes UTF-16 while agy expects raw UTF-8) (INFERRED).
Over-cap handling: chunk (docker PR#474, Chilkat), DPAPI file (GCM dpapi), or refuse (go-keyring ErrSetDataTooBig).
DPAPI: `golang.org/x/sys/windows` exposes `CryptProtectData`/`CryptUnprotectData` + `CRYPTPROTECT_UI_FORBIDDEN=0x1`/`CRYPTPROTECT_LOCAL_MACHINE=0x4` (VERIFIED v0.27.0), no cgo. Over key-based Win32-OpenSSH logons DPAPI master keys may be unavailable (S4U, 0x8009000B) (INFERRED/open).
PowerShell cost (INFERRED): no built-in cmdlet for generic creds; needs Add-Type P/Invoke (~1 s first compile) or PSGallery module; pwsh cold start ~0.3–1 s. Measured here: Go helper 3–5 ms (incl. a failed D-Bus probe); node 24–36 ms. → limitshift.{ps1,sh} never handle secrets; they call `accshift exec …`.

## 7. Recommended design
Envelope vault: OS store holds one 32-byte key; `vault.v1.bin` = header || XChaCha20-Poly1305(JSON of all accounts), AAD=header, 0600, atomic rename, flock/LockFileEx. KeySource ∈ {os-keystore, dpapi-file(Win), passphrase(Argon2id, optional keyctl @u cache with SET_TIMEOUT), plain-file(opt-in), key-file(ACCSHIFT_KEY_FILE for CI)}. Header: magic ACSV, v1, keysource id, 16-byte key-id, KDF params, 24-byte nonce.
Rationale vs one-item-per-account: single keyring access (≤1 prompt), no Windows 2560 cap, atomic multi-entry writes, uniform fallback path, easy export/migrate; cost = one "accshift vault key" item.
Per-OS key: macOS `security -i`/`find-generic-password` svc=accshift acct=vault-key-v1, 10 s timeout, exit36→unlock hint; Linux Secret Service via godbus explicit addr, collection login/default, attrs {service:accshift,username:vault-key-v1}, check Locked; Windows wincred TargetName accshift:vault-key-v1 LOCAL_MACHINE → fallback DPAPI file `%LOCALAPPDATA%\accshift\vault.key.dpapi` (UI_FORBIDDEN) on 1312.
Locations (`ACCSHIFT_HOME` overrides): Linux XDG config/data/state; macOS ~/Library/Application Support/accshift; Windows %LOCALAPPDATA%\accshift (not Roaming).
Permissions: umask 077; dirs 0700 files 0600; refuse group/other-readable vault/key (print chmod 600); Windows protected DACL via SetNamedSecurityInfo (os.Chmod meaningless); atomic write temp+fchmod+fsync+rename+dir-fsync; writers take vault.lock + per-CLI agy.lock; RLIMIT_CORE=0.
Non-interactive (default when stdin not a TTY or called by limitshift): no OS prompts; timeouts probe 3 s/op 10 s; exit codes 77=keystore locked/unavailable, 73=busy, 75=all capped. `doctor --json` reports key source, bus addr, collection lock, security exit, wincred/DPAPI probes, agy predicted mode + triggering detector, permission problems.
Migration: `store migrate --to <source>` (decrypt-reencrypt-swap-delete old key); vault versions migrated forward; import agy by capturing current slot, Claude via `claude setup-token` piped on stdin, Codex by registering CODEX_HOME dirs.
Never log/print: token values, vault plaintext, slot blobs, raw JWTs, `security -i` stdin, CLAUDE_CODE_OAUTH_TOKEN/CODEX_API_KEY/OPENAI_API_KEY/CODEX_ACCESS_TOKEN, auth.json/.credentials.json, keychain/keyring passwords/passphrases, D-Bus secret structs. Only the account label (id_token email claim decoded locally, signature unchecked, for labelling) and an optional 8-hex sha256 fingerprint. Never pass secrets as argv (ps/`/proc/*/cmdline` world-readable); env vars acceptable (`/proc/<pid>/environ` is 0400, INFERRED).

## 8. Safe agy slot swap
Preconditions: take exclusive agy.lock (bounded wait); refuse (exit 73) if any agy/antigravity/agy.exe (incl. remote-control daemon) runs for this user (agy rewrites on refresh); predict agy store mode for the queue env → file if SSH/WSL/container/empty DBUS_SESSION_BUS_ADDRESS/recent `~/.gemini/cache/antigravity-keyring-unavailable`, else keyring; also detect which slot exists.
Steps: (1) read outgoing — keyring: Linux SearchItems{service:gemini,username:antigravity} then GetSecret; macOS `security find-generic-password -s gemini -wa antigravity` strip prefix; Windows CredRead `gemini:antigravity`; or read agy's token file; (2) snapshot outgoing into the vault keyed by its id_token email; (3) write incoming in agy's exact encoding to the same slot (SS CreateItem replace=true / `security -i add-generic-password -U -X <hex base64-prefixed>` / CredWrite raw UTF-8 / file 0600) after writing a journal entry; (4) read back and verify equality; (5) clear the journal, release locks. Recovery: on startup, if a journal entry exists, re-apply or roll back. Never do Google OAuth ourselves; only move an existing login between the slot and our vault.
